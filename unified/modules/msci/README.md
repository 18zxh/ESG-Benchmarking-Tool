# MSCI ESG 评级知识库与智能评估工作台 V1

面向以简体中文和 A 股客户为主的 ESG 咨询工作：将客户上一期可持续发展报告及公司年报与 MSCI 指标要求对照，整理已有披露、披露不足和下一年度改进建议。

**V1 初始版本 · 主分支 `main` · [项目仓库](https://github.com/18zxh/MSCI_ESG_Workbench)**

使用流程：**上传与选择 → 自动初评 → 人工复核 → Excel 导出**。AI 提供披露分析建议，用户可对照原文填写评论；结果不属于官方 MSCI 评级。

## V1 包含什么

| 功能 | 支持范围 |
| --- | --- |
| 方法知识库 | 术语与符号、评级方法、评级流程、模型更新历史、关键议题，共五个模块 |
| 方法来源 | 37 份 MSCI 方法 PDF，保留来源版本、物理页码和文件指纹 |
| 指标清单 | 33 个议题、469 项环境与社会指标及子指标、107 项治理关键指标，共 576 项 |
| 报告输入 | 一份 PDF 主报告和一份可选公司年报，分别上传、保留各自原文件与页码 |
| 自动初评 | GLM 原生 PDF 分批阅读，按完整指标要求评估，支持暂停、继续及失败项重试 |
| 人工复核 | 查看初评、原文和对应 PDF 页，只编辑一项「评论」并保存 |
| Excel 导出 | 按关键议题结构导出全部已选指标、初评、出处和评论，包括未处理与失败项 |

治理默认选中 6 个议题、107 项指标。环境与社会议题需结合客户评级资料选择；全部勾选不代表全部议题均适用于该客户的官方评级。

## 在 Mac 上开始使用

日常使用需要 Python 3 和本机浏览器。前端使用原生 JavaScript，没有必须执行的 npm 构建步骤；Node.js 用于维护时重新生成指标目录。其他系统尚未完成与 Mac 同等范围的端到端验证，部分备用 PDF 组件仅支持 macOS。

1. 下载完整仓库，或克隆：

   ```sh
   git clone https://github.com/18zxh/MSCI_ESG_Workbench.git
   cd MSCI_ESG_Workbench
   ```

2. 首次使用双击 [初始化运行环境.command](初始化运行环境.command)，安装依赖。
3. 双击 [启动智能评估工作台.command](启动智能评估工作台.command)。
4. 在浏览器访问 [本机工作台](http://127.0.0.1:8770/#/workbench)。

也可以在仓库目录手动启动：

```sh
python3 -m venv .runtime
.runtime/bin/python3 -m pip install -r requirements-pdf.txt
.runtime/bin/python3 pipeline/workbench_server.py --port 8770 --open-browser
```

关闭服务终端可停止工作台。更新代码后，应停止旧服务并重新启动。若系统阻止双击 `.command` 文件，可在仓库终端执行 `sh 初始化运行环境.command` 和 `sh 启动智能评估工作台.command`。

仅阅读方法知识时，可直接打开 [打开知识库.html](打开知识库.html) 或 [离线知识库](site/msci-esg-ratings.html)。上传报告、原页预览和模型初评需要启动本机服务。

## 连接 GLM

在工作台「项目与模型设置」中填写：

| 项目 | 配置 |
| --- | --- |
| 接口地址 | `https://open.bigmodel.cn/api/paas/v4` |
| 默认模型 | `glm-5.3-flash` |
| 可选模型 | `glm-5.3-flashx` |
| API 密钥 | 使用自己的密钥，在工作台中输入 |

每次使用一个 GLM 连接。不需要安装 EmbeddingGemma；上传文件本身不调用模型，开始自动初评后才调用所连接的服务。密钥只保存在服务进程内存中，停止服务后需重新连接。

## 如何完成一次评估

### 1. 上传与选择

分别上传主报告和可选年报。每份文件须为未加密 PDF，最大 30 MiB、1–500 页；两份文件不会合并，出处按各自原 PDF 的物理页码计算。

填写客户名称、报告覆盖年度和目标披露年度，选择议题，并核对统计边界及方法适用性。报告发布日期不能代替报告覆盖年度。

### 2. 自动初评

GLM 按页面密度分批读取原 PDF，保留相关原文，再按完整指标要求生成建议判断、已有披露、披露不足、改进建议和出处。长原文分窗口处理，全部窗口完成后汇总；表格读取要求保留年度、表头、数值、单位及统计边界。

在相关全文处理完成后没有找到对应内容，显示「未披露」。读取不完整、接口中断或格式错误保留为失败项，支持单独重试，已成功结果保留。全页调度并不代表模型逐字转写或每项语义均准确。

### 3. 人工复核与导出

选择指标，查看初评及依据，打开对应主报告或年报的 PDF 页，填写并保存评论。原页预览及下载不调用模型。评论与 AI 结论分列保存，保存评论不等于采纳评分；没有适用数值标尺时不生成分数。

点击「导出评估表（Excel）」获取项目概况、框架结构、评分指标、治理关键指标，以及存在依据时的原文证据。全部已选指标都会列出，包括尚未处理和失败项。

## 数据保存、隐私与费用

- 主动保存后，原 PDF、评估及评论存入当前浏览器的本机存储。更换浏览器、端口或清理站点数据会影响草稿访问；GitHub 只保存代码，不备份客户项目。
- 远程模型会收到实际 PDF 或相关原文。重要数值、单位和统计边界可通过保留的出处与原 PDF 复核。
- API 密钥不写入源码、缓存、草稿、Excel 或 Git；请勿把密钥提交到仓库。
- GLM 缓存位于 `~/Library/Caches/MSCIWorkbench/pdf-review`。输入、模型、项目和方法版本符合条件时可复用；清理缓存或改变条件可能重新产生用量，费用以服务商账单为准。

## 开发与方法维护

| 位置 | 职责 |
| --- | --- |
| `site/` | 网页、工作台、检索、保存与 Excel 导出 |
| `site/data/` | 生成的方法数据与 AI 指标目录 |
| `site/sources/` | 37 份方法来源 PDF |
| `extract/` | 来源登记、方法结构、指标和逐页原文的维护输入 |
| `pipeline/` | 本机服务、模型代理、PDF 处理、缓存、构建与来源审计 |
| `维护资料/` | PDF 读取链路设计与准确性控制说明 |

方法内容以 `extract/` 中的维护输入为基础，网页与实际 AI 请求共用指标构建逻辑。更新方法时要同步 PDF、定义、结构、来源页码和指纹，重新生成网页数据、指标 JSON 与离线页，不能只替换 PDF 或单独手改生成文件。

详细规则见 [交接文档](交接文档.md)、[维护说明](MAINTAINER_GUIDE.md) 和 [PDF 读取链路设计](维护资料/PDF识别链路设计与准确性控制.md)。内部接口、草稿或缓存协议编号用于兼容控制，与产品发布标识 V1 分开维护。

本仓库只发布运行代码、必要文档、方法数据与方法 PDF。不包含测试脚本、测试报告、验收材料、试跑结果、客户文件、密钥、本机环境和旧 Git 开发历史。需要验证时，请在仓库之外准备获授权的公开样本和检查工具。

## 常见问题

| 情况 | 处理方式 |
| --- | --- |
| 提示缺少 PDF 组件 | 先执行初始化脚本，再启动工作台 |
| 8770 端口被占用 | 核对占用程序；若为旧工作台，停止旧服务后重新启动 |
| 离线页不能初评 | 启动本机服务，通过本机工作台地址使用 |
| 恢复后无法查看原 PDF | 在同一浏览器和端口恢复；草稿缺少原 PDF 时重新上传原文件 |
| 部分指标处理失败 | 重新连接模型后重试失败项，保留已经完成的结果 |

公开方法文件不足以复算完整官方 MSCI 评级。方法适用年度、客户所属评级行业、议题与权重仍须结合客户评级资料确认。
