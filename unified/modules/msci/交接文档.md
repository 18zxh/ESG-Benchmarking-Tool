# MSCI ESG 评级知识库与智能评估工作台 V1 · 交接文档

本仓库为 V1 初始运行版本，正式维护分支为 `main`。面向后续开发与维护人员；日常使用见 [README](README.md)，读取设计见 [PDF 识别链路设计与准确性控制](维护资料/PDF识别链路设计与准确性控制.md)。产品发布标识与内部接口、缓存协议编号分别维护。

## 一、产品目的与现状

工作台用于将客户上一期可持续发展报告及年报与 MSCI 指标要求对照，定位已披露内容、披露不足和下一年度改进方向。主要用户为处理简体中文、A 股客户报告的 ESG 咨询人员。

| 内容 | 交接状态 |
| --- | --- |
| 产品名称 | MSCI ESG 评级知识库与智能评估工作台 |
| 运行形式 | 本机 Python 服务与浏览器网页 |
| 工作台页面 | 上传与选择、自动初评、人工复核 |
| 报告输入 | 一份主报告及一份可选年报，均为 PDF，独立上传 |
| 方法资料 | 五个知识模块、37 份来源 PDF |
| 指标数量 | 33 个议题、469 项环境与社会指标及子指标、107 项治理关键指标，共 576 项 |
| 默认范围 | 治理 6 个议题、107 项指标 |
| 当前默认模型 | `glm-5.3-flash`，中国区接口 |
| 人工操作 | 对照原文填写评论；保存评论不自动确认模型评分 |
| 导出 | 单一评估 Excel，按关键议题结构组织 |

没有 Markdown 上传入口。原 PDF、方法来源和历史项目应继续保留。全部议题属于检查范围，不等于某家公司官方适用议题或权重；AI 建议及“不适用”判断不等于正式评级。

## 二、运行与环境

主要运行环境为 macOS 与 Python 3；Node.js 用于方法指标数据生成，网页没有必须执行的 npm 构建步骤。

日常通过两个 `.command` 文件初始化并启动，完整命令见 [README](README.md#快速开始)。本机默认地址为 `http://127.0.0.1:8770/#/workbench`，服务只绑定回环地址。

Python 依赖登记在 [requirements-pdf.txt](requirements-pdf.txt)：`pdfplumber==0.11.9`、`PyPDF2==3.0.1`，其传递依赖提供原页渲染能力。GLM 全文初评不依赖 macOS OCR；其他模型的本机文字和图像识别使用 PDFKit、Vision 与表格识别组件。Windows、Linux、Intel Mac 未完成同等范围的端到端实测。

启动脚本优先使用 `.runtime/bin/python3`，否则使用本机 `python3`。它会检查端口对应的 `appId` 与接口版本，仅复用相同应用且版本不低于 6 的服务。更新后出现旧服务提示，应停止旧进程后重新启动，不能仅刷新网页。

离线文件 `site/msci-esg-ratings.html` 内嵌 37 份方法 PDF，可用于方法阅读与导出；报告处理和初评使用本机服务。

## 四、评估数据流与关键约束

### 原生 PDF 全文模式

1. 用户分别上传主报告与年报。后端校验文件，登记原始 SHA-256，读取可用文字层并准备文档；上传完成不等于模型已阅读全文。
2. 点击开始后，所选 GLM 服务分批读取全部物理页，为所选议题提取相关原文。初始调度最多 12 页，按文字密度及扫描页估算调整；请求副本超过 6 MiB 在调用前拆小。每批最多 32 条摘录、每条最多 1,200 字；过密、明确不完整或输出达到上限时拆小。单页未完整保留仍失败，不写入成功缓存。文字层读取异常时保留原 PDF 视觉通道。
3. 读取完成后，按议题分组，调度组最多 16 项、实际单次最多 8 项；完整输入估算预算为 12,000，窗口结果合并预算为 28,000。相同要求字段共享发送，展开后与原要求完全一致。原文过多就划分所有窗口，逐个完成后按指标两两汇总，携带前序结论及所引用的原文；不会用前几条原文替代尾部内容。合并说明保持简短，最多 8 条直接引用，保留年度、边界及矛盾。超过预算或窗口失败保留失败状态，不截断定义或原文，也不生成全文未披露结论。估算并非服务商分词计量或费用保证。
4. 前端显示判断、披露、不足、建议及出处。复核使用原文件的对应页，评论与模型结果分开保存，最后导出 Excel。

全文模式当前识别的模型名为 `glm-5.3-flash` 与 `glm-5.3-flashx`；用户指定的默认值和真实全量验收使用 Flash。接入其他原生 PDF 模型时，需要同步前后端能力识别及请求契约，不能仅改默认模型名称。

### 必须保持的行为

- 主报告与年报分别保留文件、名称、物理页数、预览及下载。年报第 1 页不能被换算成主报告后的连续页码。
- 请求用 PDF 副本增加物理页标记，原文件不修改。自动出处对齐只使用明确原文或数字锚点，含糊匹配不猜页码。
- 未找到披露显示「未披露」。读页、传输、JSON、遗漏指标和非法出处等技术失败必须保留失败状态。
- 已披露判断需要有效出处；「未披露」不能同时带引用。没有适用数值标尺时保留空分数。
- 已成功的单项与评论不能因其他项目失败而丢失。重试只补待处理或失败项，服务重启后先恢复原 PDF 登记与缓存。
- 人工复核只有评论入口。旧记录中的人工确认历史可保留，不能把新的评论保存视为确认或采纳模型结论。
- 相关摘录不等于报告逐字转写；“全部物理页提交”不能被描述为“模型绝无遗漏”。

当前服务的界面仅显示 GLM 连接并单选；隐藏备用语义检索和图表转述选项。旧版服务的相关原文路径及历史记录仍兼容，兼容测试单独保留。后续移除备用模块前应先审查历史草稿与导出，避免破坏用户记录。

原生任务调用 `aiRequirementsForIssues` 构建完整指标。静态 JSON 快照由同一函数生成，额外登记来源版本与指纹，不含客户资料、评论或密钥。维护时先更新 `extract/` 和对应生成数据，再构建 JSON 与离线 HTML，避免另建一套手工维护的指标。该数据模块只用于评估与维护，工作台不提供评级依据查看入口。

## 五、接口概览

当前 `/api/status` 返回接口版本 6，应用标识 `msci-esg-pdf-workbench`，并声明 `nativePdfReview: true`。启动器不复用旧版本服务；更新后须重启。

| 接口 | 用途 |
| --- | --- |
| `GET /api/status` | 应用版本与已连接服务的公开信息 |
| `POST /api/providers` | 在进程内连接模型服务 |
| `POST /api/native-documents` | 登记原生全文模式的 PDF |
| `POST /api/pdf-review` | 创建全文读取与指标初评任务 |
| `GET /api/pdf-review/<任务编号>` | 获取页数、进度、结果、错误及已返回用量 |
| `POST /api/pdf-review/<任务编号>` | 暂停、继续或停止任务 |
| `POST /api/pdf-page` | 本机渲染指定原 PDF 物理页 |
| `POST /api/parse-pdf`、`GET /api/pdf-jobs/<任务编号>` | 其他模型使用的本机异步解析 |
| `POST /api/evaluate` | 其他模型的逐指标初评 |
| `POST /api/figure-text` | 可选图表转述 |

PDF 请求使用 `application/pdf`，文件名位于 `X-File-Name`；原页预览另传 `X-PDF-Page`。JSON 请求按接口契约提供字段。Host 与 Origin 校验应继续限制为本机；上游 TLS 验证、日志不记录凭据与原文的约束需保留。

## 六、保存、缓存与凭据

| 数据 | 保存位置 | 生命周期 |
| --- | --- | --- |
| 连接密钥 | 本机服务进程内存 | 服务停止后清除，需重新连接 |
| 原生 PDF 登记与任务 | 服务内存 | 数量有限，重启失效；恢复时重新登记 |
| 备用本机解析任务 | 服务内存 | 最近有限结果，完成或失败后 5 分钟过期 |
| 原 PDF、评估与评论 | 当前浏览器 IndexedDB | 点击保存后保留；依赖浏览器及站点来源 |
| GLM 阅读缓存 | `~/Library/Caches/MSCIWorkbench/pdf-review` | 最多 120 个有效读取批次 |
| GLM 初评缓存 | 上述目录的 `assessments/` | 最多 150 组有效初评 |

浏览器草稿目前使用 `schema: 5`。客户、报告年度、目标年度、统计边界、主报告与年报的组合、方法身份共同影响记录隔离。改变保存结构时应保留旧草稿可恢复性，不能仅替换字段后丢弃原 PDF 或评论。

读取缓存绑定读取版本、文件名、原文件内容、主报告或年报来源、服务地址、模型、议题及批次页段。初评缓存另外绑定完整指标、原文和项目背景。有效结果写入本机磁盘，可跨服务重启复用。

`pipeline/pdf_assessment.py` 当前读取版本为 `native-pdf-review-v2`，初评版本为 `native-assessment-v3`。改变读取提示、摘录或输出契约时更新 `VERSION`；改变评估输入或结论契约时更新 `ASSESSMENT_VERSION`，防止沿用旧结果。新版首次运行不会复用旧提示版本缓存，可能重新产生用量。两种模型名称能力及结构化输出依据见 [GLM 官方文档](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash)。

不要在源码、示例、Git、日志、导出或配置文件中加入真实密钥。客户报告、完整响应与本机缓存不随仓库上传。使用远程模型时，实际 PDF、文本或图表按相应流程发送给用户选定服务商；本机保存不代表模型处理全部发生在本机。

## 七、方法资料更新

1. 先保留旧方法文件、来源清单和当前 Git 提交，确认新文件的适用年度、版本、页数与对应模块。
2. 在 `site/sources/` 更新来源 PDF，在 `extract/sources.json` 更新登记、页数及 SHA-256；同步维护对应原文资料。
3. 核对并更新 `extract/key_issues.json`、`core_modules.json`、`structure.json`、`metadata.json` 中受影响的定义、规则、层级、中文解释及引用页数。不得把软件更新时间当作方法适用日期。
4. 运行来源审计。审计脚本含当前版本的核心页段映射，换版时应按新原文核实映射，不应为消除错误而直接删除检查。
5. 重新生成数据与离线网页，并运行相关回归和真实原页抽查。方法变化应形成新的指标指纹，旧项目及评论继续保留原版本。

构建与审计命令：

```sh
mkdir -p .runtime/checks
.runtime/bin/python3 pipeline/build_data.py
node pipeline/build_ai_requirements.mjs
.runtime/bin/python3 pipeline/audit_sources.py .runtime/checks/来源审计.json
.runtime/bin/python3 pipeline/build_standalone.py
```

完成核验后可运行 `.runtime/bin/python3 pipeline/build_release.py`。脚本将 ZIP 与清单写在仓库同级，保留当前可执行文件权限。核对包内文件、来源指纹和密钥扫描后交付。

## 八、验证与交付

本仓库发布运行版本，不分发自动测试脚本、测试样本、试跑输出或验收材料。完整旧开发历史和测试资料在本机归档保留；维护人员需要测试工具时从本机备份获取，在仓库之外运行。

发布前按改动范围核对：

| 修改内容 | 对应检查 |
| --- | --- |
| 文档 | 本地链接、启动命令、依赖、路径与密钥扫描 |
| 页面或保存交互 | 桌面与窄屏、键盘操作、评论保存及恢复 |
| PDF 读取与模型契约 | 公开小样本、页码与文件来源、失败重试和上下文预算 |
| 方法资料 | 来源审计、指纹、指标数量与层级、原 PDF 定位 |
| 导出 | 实际生成 Excel，核对完整指标、出处与评论 |

真实模型验证先使用小范围公开报告，记录服务商用量，只在完整读取或全量指标发生变化时扩大范围。源码、接口或结构检查不能保证每个字符和模型判断都正确。

## 九、仓库与协作约定

当前正式分支为 `main`。在干净工作区同步代码：

```sh
git switch main
git pull --ff-only origin main
```

提交前核对实际 diff、验证范围和密钥；多人或多工具同时修改时使用独立功能分支，完成检查后合入 `main`。更新代码不迁移浏览器草稿，也不自动更新已运行的本机服务。

当前仓库仅保留运行代码、必要文档、方法数据和 37 份来源 PDF，以 V1 作为初始运行版本。测试脚本、样本、试跑结果和旧开发历史不上传。

`.gitignore` 排除运行环境、依赖、缓存、日志、私密配置、测试脚本、测试样本和验收材料。公开报告测试及完整响应均放在仓库外，不向运行仓库提交客户文件或密钥。

## 十、已知边界与后续扩展

- PDF 页数覆盖、结构检查和模型格式通过不能代替语义准确性保证。扫描件、复杂表格、数值单位和统计边界仍可借助原页复核。
- 只有收到的上游响应才能累计对应任务用量；网络中断不能据此认定服务商未计费。缓存复用也取决于版本与项目条件。
- 方法适用年度、客户行业及官方评级权重需结合客户评级资料确认，不能由默认清单推定。
- 当前为本地浏览器应用，尚未交付 DMG 安装包。后续桌面封装需继续管理本机服务、运行依赖、OCR 组件、用户数据位置与升级兼容性，再做安装、重启及迁移实测。
- 后续加入其他评级，可复用上传、项目保存、原页预览和导出基础；各评级的方法资料、指标身份、适用性与评估提示分别维护，不能用相同界面推定相同评分逻辑。
