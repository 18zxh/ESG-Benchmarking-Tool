# 维护说明

## 文件与职责

- `extract/`、`site/data/core.js`、`site/data/key-issues.js`：来源事实、版本与知识结构。五个知识模块的 37 份方法 PDF 与客户上传报告是两类资料，不应混放。
- `site/app.js`、`site/index.html`、`site/styles.css`：知识阅读、查询、导航及共用风格。
- `site/workbench.js`：三页交互、PDF 上传进度、评论和主动保存；不在此处实现模型规则或 Excel 行结构。
- `site/workbench-core.js`：指标身份、提取块分段、全文检索、模型结果检查和记录隔离。
- `site/workbench-batch.js`：相关依据、邻近段落与统计边界选取，以及暂停、继续、重试队列。
- `site/workbench-export.js`、`site/xlsx.js`：关键议题结构评估表及浏览器 Excel 写入；后者亦供知识模块导出使用。
- `pipeline/pdf_convert.m`、`pipeline/pdf_conversion.py`：客户 PDF 的文字层、全页图像、坐标、表格与异常；与方法数据构建分开。
- `pipeline/workbench_server.py`：仅本机服务、解析任务、模型连接与请求核验。

## 更新方法资料

先完整备份或新建独立目录。保留当前方法 PDF、来源版本、SHA-256、适用年度及旧结果；新文件不能覆盖旧方法并仍沿用旧指纹。逐页检查新方法的定义、组件、层级、父指标、评分规则与适用范围，不能依靠标题相同认定未变。中文解释须人工对照新原文。

更新 extract 中的来源和结构，再重新生成相应站点数据。指标身份包含定义与版本内容；改动方法后旧记录仍作为历史保留，不套用到新指标。治理默认全选只提供检查清单，官方客户适用范围必须核实。

依次运行来源核验、数据检查、相关路由与导出回归。`pipeline/audit_sources.py` 检查英文定义覆盖、原文、引用页码和文件指纹，不能认证所有中文解释或 MSCI 未公开的评分算法。不要自动把软件更新日期写成方法核对日期。

## PDF 阅读与初评

V1 默认使用 GLM 原生 PDF 链路：独立保留主报告与年报原件、文件指纹、来源类型和物理页码；上传不等于模型已阅读全文。按页段与内容密度拆批阅读，核对请求页号、完整性声明和输出是否触顶。文字层异常时仍保留原 PDF 的视觉通道。

按完整方法要求生成初评；重复共同字段合并，长原文在预算内分窗口处理，全部窗口完成后汇总。不得为节约上下文而静默丢弃指标或原文尾部。技术失败保留失败状态；全文处理完成仍无对应材料时显示「未披露」。原文与评分规则不足时不推定数值评分。

`pipeline/pdf_assessment.py`、`pdf_context.py`、`pdf_pages.py` 与 `site/workbench-native.js` 负责当前默认流程。`pdf_conversion.py`、`pdf_convert.m` 和 `bin/` 为本机识别兼容组件；16 MB 本机文字限制、每项检索片段限制不等同于 GLM 全文模式上限。当前默认模型为 `glm-5.3-flash`，每次使用一个 GLM 连接。

模型意见、文件名、页码、披露现状、不足及建议保留出处。人工只编辑评论，评论与模型结论分列保存。客户、报告期间、目标期间、统计边界、报告指纹与方法身份共同决定记录隔离。

## Excel 与保存

评估只有一个 Excel 导出入口。项目概况、框架结构、环境社会评分指标、治理关键指标、有依据时的原文证据分别呈现；全部已选指标含未处理及失败项都列行。环境社会保留支柱、主题、议题、组件、层级与父项；治理保留类别和关键指标。原文、判断、不足、建议、出处、方法版本和评论保留。原方法英文规则是来源原文，不应为了界面中文而改写。超长单元格采用保留身份的续行；文本用内联字符串，不能执行输入中的公式。

只有点击保存才将原 PDF、提取结果、评估及评论存入当前浏览器本机 IndexedDB。保存副本不是云备份；换浏览器、换端口或清理站点数据不会自动迁移旧草稿。旧版本和旧端口保留，可回到原版本读取历史。导出不包含连接密钥。

## 运行与发布

当前默认本机地址 `http://127.0.0.1:8770/#/workbench`。启动脚本只复用相同 appId 且接口版本不低于 6 的服务。其他服务占用该端口时明确提示，不杀掉未知进程。首次运行缺组件时使用初始化脚本安装固定 PDF 依赖。

API 密钥只保存服务进程内存，不写配置、文件、Git、日志或进程参数，停止服务即清除。真实模型回归只使用获授权的公开报告。服务连通与模型质量须以实际请求结果为依据。

重建 `pipeline/build_standalone.py` 的离线单文件并核对 37 个内嵌 PDF；重建 `pipeline/build_release.py` 的源码压缩包，逐文件核对哈希、ZIP CRC、转换器可执行位及密钥扫描。运行环境、缓存、日志、Git、开发截图不进入发布包。

## 验证与界面

相关检查包括 Python 后端边界、长表/数字/扫描 PDF、引用与评分限制、相应交互检查、真实接口、真实模型、浏览器上传/保存/恢复/下载以及桌面和窄屏截图。记录每一类的实际范围，模拟不能写成真实浏览器通过，一项真实初评不能写成全部 576 项已评估。

视觉采用白色森林绿、系统简体中文与细分隔线。三页原生 tab/tabpanel；桌面双列、窄屏单列，初评在 1200px 以下按指标纵向呈现。证据采用可折叠出处和可键盘滚动的完整摘录。仅评论输入突出，其余详情按需展开。正常操作用中文，去掉软件日期徽标，保留报告年份与方法来源版本。

DESIGN.md frontmatter 与 `.impeccable/design.json` 保留为现有系统权威；普通扩展不重建整个设计系统。新增行为在 Components/Layout 中按实情补充。使用以 README、交接文档和当前源码为准。

## 运行仓库范围

当前 GitHub 仓库不分发测试脚本、测试 PDF、试跑结果与验收记录；旧开发历史和测试资料保留在本机备份。上述验证规则仍适用，维护人员在仓库外准备公开样本并保存检查结果。
