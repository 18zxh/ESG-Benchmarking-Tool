# V1 架构与代码维护

前端使用原生浏览器模块；网站运行不需要 Node、构建工具或新前端框架。后台为本机 Python 服务。开发工具与历史过程材料在本机独立归档，不进入网站运行依赖。

## 前端职责

| 文件／目录 | 职责 |
| --- | --- |
| `site/app.js` | 启动、页面分发、导航及事件绑定；工作台和资料控制器首次打开时加载 |
| `site/router.js` | 路由名称、筛选参数、链接及旧入口兼容 |
| `site/data-store.js` | JSON 读取和缓存，失败时移除缓存以允许重试 |
| `site/ui.js` | 页面标题、选项、表格、分页和提示等共享显示函数 |
| `site/pages/` | 概览、行业权重、问题、搜索及年度变化；页面数据由入口传入 |
| `site/methods.js` | 方法 PDF 导读 |
| `site/question-reader.js`、`question-layout.js` | 来源一致性保护、中英文一级主问题展示及完整来源的 Excel 分块 |
| `site/data/question-primary.json` | 一级展示索引、共享主问题及少量带依据的展示修补；不覆盖原题数据 |
| `site/question-export.js`、`xlsx.js` | 标准问题库表格结构及 XLSX 文件生成 |
| `site/assessment-method.js`、`site/data/assessment-method-schema.json` | 按同一字段清单生成行业方法 Excel 与工作台本次选题 Excel |
| `site/workbench.js` | 工作台操作、上传、检索、模型请求、PDF 对照与项目成果导出 |
| `site/workbench-view.js` | 工作台三个步骤的显示；不保存项目、不发起模型调用 |
| `site/reports.js` | 资料类型、上传容量／指纹规则、期间提醒及 PDF 片段生成 |
| `site/evidence.js`、`retrieval-ranking.js` | 候选原文与披露初评；完整问题查询、BM25、关键词及质量排序（兼容文本模型与旧项目） |
| `site/task-queue.js`、`model-evaluation.js` | 逐题任务的暂停／继续／停止；完整 CSA 方法输入及模型请求 |
| `site/project.js`、`project-export.js` | 项目格式、浏览器保存／恢复及项目证据行导出 |
| `site/resources.js` | 分类资料与门户 PDF 登记 |
| `site/styles.css` | 全站样式；原两份样式合并，保留原级联顺序 |

`core.js` 保留共享术语、名称和简单方法规则。每个页面显式接受所需数据。模块不导入 `app.js`；入口可以调用模块，模块之间保持单向依赖。新页面放入 `pages/`，在 `router.js` 登记入口；业务规则放入对应领域模块。

问题页不再渲染完整分支、表格或嵌套说明。页面和 Excel 的一级表共用 `primaryQuestion()`；它先核对七项完整来源，再验证英文主句确实存在于所引用字段。整段结构仅在导出完整来源表时加载。

保存使用原有两个 IndexedDB 数据库：`csa-local-workbench` 和 `csa-questionnaire-register`。V1沿用这些保存结构。

本版不使用 EmbeddingGemma 或向量控件；历史项目和已保存原 PDF 保留，新界面不读取或准备向量索引。

`site/native-pdf.js` 负责原 PDF 数据、异步任务轮询和备注应用；`pipeline/native_pdf.py` 校验原文件指纹与行业问题，按连续物理页拆分 PDF，分批调用 GLM 读取并核对页覆盖，再把相关原文和完整方法要求送入分批初评。AI 方法字段由 `assessment-method-schema.json` 读取，和前端导出共用同一份字段定义。行业题目与可启用状态仍来自同一份原始数据。

长表格按行拆分，各段携带原始表头及附近单位／脚注。超过单段预算的上下文保留为同页独立来源片段，并明确提醒核对原 PDF；原解析数据完整保留。显示页的一级主问题不作为完整评估方法的替代。

## 方法 Excel 与 AI 请求的一致性

`assessment-method-schema.json` 是方法记录的字段契约。前端的按行业方法导出与工作台选题导出由 `assessment-method.js` 生成；Python 侧的 `_assessment_method_record()` 按同一 JSON 字段清单组装 GLM 请求。导出时的空值按空单元格处理，AI 入参同样规范为空字符串。项目背景和 `evidence` 原文属于评估上下文，明确与方法字段分开。

调整字段时必须同时保留字段顺序、键名、来源字段和译文字段定义，使用单独保留的维护检查工具，逐行业比较实际XLSX单元格与后端构造的完整GLM方法对象，再核对本次选题导出子集；不得只比页面主问题。维护工具不作为运行版依赖，不随V1发布。

GLM 读取分成“报告逐页摘录”和“问题初评”两阶段。每段最多12页，并同时控制定位文本和 PDF 文件体积；完整读页清单不匹配、输出不完整或摘录数量超限时自动拆小。单页仍过载时再按问题主题拆分；进度按已覆盖物理页去重。逐页读取结果仅保留能与同一原 PDF 物理页连续匹配的原文；问题初评只收到相关摘录和完整 CSA 方法，不重复接收整份报告。失败页段不会形成全文未披露结论，成功页段、拆分决策和逐题范围持久保存，按文件指纹、模型、完整方法和阅读协议区分；细节见下文持久缓存章节。工作台只允许 GLM-5.3-Flash 系列连接，默认 `glm-5.3-flash`；FlashX 为可选 GLM 型号。

这些检查保证请求页段和引用位置有程序校验，不保证模型语义理解无遗漏。每题备注及引用仍待用户确认，人工只需加备注。原文和 PDF 物理页码继续可对照；未保存草稿不进入 Excel。旧项目格式继续兼容。

## 后台职责

| 文件 | 职责 |
| --- | --- |
| `pipeline/workbench_server.py` | 本机 HTTP、来源文件、下载、请求大小与来源校验；服务版本 6 |
| `pipeline/native_pdf.py` | 原生 PDF 文件、官方题目校验、连续引文定位和备注生成 |
| `pipeline/native_pdf_jobs.py` | GLM 逐页读取与初评的异步任务、进度及结果保留 |
| `pipeline/pdf_quotes.py` | 从原 PDF 建立独立读序与图片文字定位；最多缓存六份／32 MiB，引用不能跨读序拼接 |
| `pipeline/model_proxy.py` | 通用评估结果校验与 GLM Chat Completions 请求构造；本机入口只允许官方 GLM 连接 |
| `pipeline/pdf_jobs.py` | 内存中的 PDF 解析任务、进度和过期结果清理 |
| `pipeline/pdf_conversion.py` | 本机 PDF 文字、图像及表格处理 |
| `pipeline/errors.py` | 各服务共用的请求错误类型 |

`/api/industry-lookup` 与行业模型模块已删除。模型连接、报告初评、PDF 处理和下载接口继续由各自模块维护。模型密钥仍只在内存中；网站只绑定本机地址。入口通过服务对象调用业务模块，避免把模型名称变量与模块名称混用。

## 维护原则

1. 方法来源更新独立于界面重构。行业、权重、原文、译文、模板与启用状态仍须按原 PDF 核对。
2. 共享显示函数统一维护；新页面使用现有函数，避免复制第二套选项、分页或路由处理。
3. 每个控制器只绑定一次事件。页面重绘只生成显示，不重新注册监听器。
4. 删除功能时同时处理入口、模块、接口、样式和使用说明；先备份，再移除文件。
5. 评估或保存逻辑变更时另行验证完整流程。静态引用审阅与页面截图不能代替报告处理及保存／导出的功能验证。

本轮静态审阅记录确认没有失效的模块导入或循环依赖；这表示当前代码边界清楚，不代表未来修改无需复核。


## 持久缓存和逐题增量

`pipeline/workbench_runtime.py` 提供SQLite事务存储、稳定JSON指纹、运行上下文、任务检查点和usage记录，不读取CSA题库。`pipeline/csa_adapter.py` 承担2026 Full适用题读取和完整方法记录生成，原有Python函数名继续可用，便于一致性检查。

`native_pdf.py` 仍是CSA专属的阅读与初评编排器。读取复用按企业/行业范围、PDF指纹、完整方法、服务/模型、源码/字段契约、实际页段区分；完成页段及拆分决策落盘，完整报告范围另按题保存。一次读取中的其他题目不自动获得已读资格。被拒摘录数量与OCR待核实标记随缓存恢复。

初评缓存额外包括全部报告清单、来源/类型/期间/公开性、企业背景、已核验原文和不确定性。重绑定报告名称/ID后重新生成证据编号，避免跨项目引用旧ID。新增报告仅阅读新文件，但当前所有题目的初评保守失效；删除报告亦按新的完整输入重评，若新输入恰好匹配更早的有效结果则可复用该结果。

`native_pdf_jobs.py` 保存不含密钥/原PDF请求体的任务快照。旧进程退出后，未完成任务查询转为interrupted，用户重新提供连接与原文件后，通过正常入口重建任务并复用完成范围。部分初评批次缺题或逐题校验失败时，合格题逐题落盘，错误题留待续跑；未知/重复ID会拒绝该批。

可选紧凑模式采用顶层共用evidence表，各题以evidenceIds引用；完整方法字段和值保持原样。由于完整真实报告对照未通过，本版默认关闭此模式，保留逐题证据结构。按照实际序列化的项目背景、方法、证据和系统提示长度分批，仍设12题/56,000字符上限及输出预算，超限不截去方法。原PDF定位锚点未精简，避免未经对照便降低召回。

通用存储可单独复用；分页、模型提示词和语义校验仍在CSA模块中，尚未发布跨评级通用引擎。其他工作台的接入需要独立适配和验证。


### 最终控制与缓存边界

- 运行上下文固定启动时源码版本，方法记录固定本次schema字段快照；后台源码变更须重启，避免运行中的旧逻辑生成新版本缓存键。
- Store/Run为通用存储与计量层；`before_request`钩子承接暂停/继续/停止。任务队列仍为单工作线程，相同活跃请求复用任务，服务退出会唤醒暂停线程。
- 前端只在缓存未命中的阅读中由后台建立引文定位，不再为每次续跑预先重复解析整份PDF。完整缓存命中无需新的PDF定位或模型请求。
- 增删资料及修改来源/期间使当前模型草稿失效并保留历史；移除资料后清理当前引用。人工已保存备注和未保存草稿独立保留；未重评的历史结果明确标记待更新。
- 提供 `/api/native-pdf-jobs/<id>/control` 与 `/api/native-pdf-cache/clear`，沿用本机来源校验；活跃任务期间拒绝清理缓存。
- 常规源码更新使旧合同缓存正常失效。任何单独迁移须先核对阅读语义、PDF/完整方法指纹与连续原文，不能以迁移名义把旧结论强行当新版本完成。

真实调用限制、已读断点与回退步骤见 `HANDOFF.md`；测试文件和报告仅保留在本机。
