# 指引工作台 · V1

面向 ESG 报告编制与审阅的本机工作台，将交易所披露要求、报告原文和同业对标放在同一条工作流程中。

**首个公开版本：1.0.0** · macOS · Python 3.12 · GLM

## 三个工作入口

| 模块 | 用途 | 主要输出 |
| --- | --- | --- |
| 大陆交易所 | 按上海、深圳、北京交易所指引核对报告，统一管理 21 个议题 | 议题判断、原文证据、人工评论与评估 Excel |
| 香港交易所 | 按附录 C2、发行人类别及财政年度核对适用要求 | 中文条文对照、逐项判断、证据与评估 Excel |
| 横向对标 | 将多家公司不同名称的报告章节映射到统一议题 | 231 项 Yes/N 矩阵、同业覆盖率与对标 Excel |

两个交易所模块各有知识库和工作台。知识库用于查阅条文与适用安排；工作台用于上传报告、映射章节、核对披露、查看原页和记录人工意见。

## 快速开始

### 1. 准备环境

需要 **macOS 和 Python 3.12**。首次初始化需联网安装依赖；日常运行无需 Node.js。

[下载源码 ZIP](https://github.com/18zxh/Stock_Exchange_ESG_Workbench/archive/refs/heads/main.zip)，解压到本机可写目录后：

1. 双击 `初始化运行环境.command`，建立项目独立运行环境并安装依赖。
2. 双击 `启动智能评估工作台.command`，浏览器自动打开功能入口。
3. 选择模块，在“模型服务设置”中填写自己的 GLM 接口、模型名和 API Key。

也可在项目目录通过终端启动：

```sh
./初始化运行环境.command
./启动智能评估工作台.command
```

若下载后脚本没有执行权限，可先运行：

```sh
chmod +x 初始化运行环境.command 启动智能评估工作台.command
```

默认地址为 `http://127.0.0.1:8791/#/markets`。端口占用时顺延，实际地址以启动终端为准。服务只监听本机回环地址，在启动终端按 Control-C 停止服务。

### 2. 配置模型与上传报告

只支持 GLM 原生 PDF 流程。填写智谱或 Z.ai 官方接口和支持 PDF 输入的模型；默认模型名为 `glm-5.3-flash`，模型权限及实际兼容性以服务商响应为准。

每份 PDF 须未加密，大小不超过 **30 MB**，物理页数为 **1–500 页**。文件登记、模型连接登记均不代表全文读取已经成功。

## 报告审阅流程

1. **配置项目**：填写客户、报告覆盖年度、目标披露年度及交易所条件。港交所还需填写发行人类别和财政年度开始日期。
2. **上传文件**：主报告用于章节映射；可选公司年报仅补充已映射议题的证据，两份文件各自保留物理页码。
3. **对齐章节**：将报告自定义的章节或议题名称映射到统一检查项，可人工修正与撤销。
4. **逐项核对**：先预检首页，再连续分批读取；支持暂停、继续、停止和失败重试。读取未完成时保留失败，不生成“全文未披露”结论。
5. **人工复核**：查看判断、披露不足与建议，点击出处打开本机 PDF 原页，独立填写评论。
6. **保存与导出**：主动保存草稿以便恢复，或导出含规则、判断、原文证据和 AI 评级依据的 Excel。

系统不生成官方评级或数值评分。全页提交与结构校验不能保证模型没有语义遗漏，关键结论应回到报告原页复核。

## 多公司横向对标

在首页进入“横向对标”，一次添加多份 ESG 报告，分别填写公司与覆盖年度。每家公司只纳入一份报告；不同覆盖年度会在表头标明。

对标按 **21 个议题 × 11 个二级检查项**展开为 231 行。二级检查项分属治理、战略、影响/风险/机遇管理、指标与目标四个一级。公司章节名称不同，仍可通过映射归入同一议题。

| 单元格 | 含义 |
| --- | --- |
| Yes | 发现对应披露，并附可追溯原文与 PDF 物理页 |
| N | 完整读取和核对后，未发现对应披露 |
| 空白或未完成 | 尚未处理或核对失败，不计作 N |

可以指定一家公司为本公司，其余为同业。每行按以下口径计算：

**同业覆盖率 = 披露该项的同业公司数 ÷ 该行已完成核对的同业公司数**

分母不含本公司和未完成项；页面同时列出已完成数与同业总数。点击 Yes/N 查看判断依据，导出包含“同一议题对标、判断与原文证据、议题映射、项目与口径”四张工作表。

对标框架见 [`data/benchmark/framework.json`](data/benchmark/framework.json)。这是披露对照口径，不构成新增法规义务，也不比较绩效数值高低。

## 规则与依据

### 大陆交易所

使用 2024 年试行指引整理的规则，三所各 21 个议题：环境 8、社会 9、治理 4。本版不宣称已覆盖其后法规修订。

- [上交所试行指引 PDF](上海证券交易所上市公司自律监管指引第14号——可持续发展报告（试行）.pdf)
- [深交所试行指引 PDF](深圳证券交易所上市公司自律监管指引第17号——可持续发展报告（试行）.pdf)
- [北交所条款 Markdown](北京证券交易所上市公司持续监管指引第11号——可持续发展报告（试行）.md)

三所条款 Markdown、结构化规则及来源指纹随仓库提供。北交所原始 DOCX 不在公开范围内；原始材料未包含第 59 条提及的附表，页面保留该来源限制。

### 香港交易所

使用官方主板及 GEM《上市规则》附录 C2 中文依据：主板 69 项、GEM 71 项。适用属性按发行人类别和财政年度开始日期计算。附录 C1 企业管治守则属于独立规则体系。

- [主板附录 C2 官方繁体 PDF](data/sources/hkex/mb-c2-current-tc.pdf)
- [GEM 附录 C2 官方繁体 PDF](data/sources/hkex/gem-c2-current-tc.pdf)
- [来源、获取日期与指纹](data/sources/hkex/hk-zh-manifest.json)

知识库显示文本由官方繁体正文离线简繁转换，简体显示文本并非官方原件。条文注释、适用条件和宽免仍须结合发行人情况逐项核定，监管要求以交易所官方现行版本为准。

检查问题和评估方法在 [`data/assessment/`](data/assessment/)；结构化条文在 [`data/ruleset/`](data/ruleset/)。知识库、模型请求与导出共用对应条文及方法，报告证据按本次任务动态加入。

## 数据与隐私

- **密钥**只保存在本机 Python 服务内存中，不写入源码、草稿、缓存、导出或日志；服务停止后需重新登记。
- **草稿与原报告**由用户主动保存到当前浏览器地址（含端口）的 IndexedDB。更换浏览器、端口或清理站点数据不会自动迁移草稿。
- **模型请求**会将报告页段和原文证据发送至配置的 GLM 服务。项目草稿不自动上传云端。
- **本机缓存**位于 `~/Library/Caches/ExchangeSustainabilityWorkbench/`，用于复用有效读取和核对结果，可以丢弃。

本仓库只发布代码、运行规则、交易所依据文件及功能测试，不含客户报告、凭据、原始用户表格、内部 PRD/规划记录或本地开发历史。

## 开发与验证

前端为原生 JavaScript 和静态 HTML/CSS，后端为 Python 3.12 标准库 HTTP 服务。PDF 依赖为 `pdfplumber==0.11.9`、`PyPDF2==3.0.1`。日常运行没有前端构建步骤。

完成初始化后，可运行使用合成 PDF 与模拟模型的 Python 功能测试：

```sh
.venv/bin/python -m unittest discover -s pipeline -p 'test_*.py' -v
```

前端测试另需 Node.js 22：

```sh
npm install --prefix .runtime/qa --no-save happy-dom@20.14.5 fake-indexeddb@6.2.5
npm test
```

自动测试不调用付费模型。模拟流程与界面核验不代表真实 GLM 已完成整本报告评估；另一台全新 Mac 的安装仍需单独验证。本版为本机源码应用，不提供云托管、自动监管报送或 DMG 安装包。
